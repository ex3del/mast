# MAST

*English version: [README.md](README.md)*

MAST — Method for Agents, Sessions and Tasks. Плагин Claude Code, который приносит в проект
способ работы: пункты роадмапа с измеримыми критериями готовности, worktree на пункт,
диспетчер для параллельной работы, правила с `paths:`, архив закрытого. Плагин не трогает
глобальный `~/.claude/CLAUDE.md` и ничего не пишет в ваш проект без вопроса. Сам Claude Code
записывает включение плагина в ваш `settings.json` — такая же служебная запись, как у любого
плагина, — а метод и его хуки туда ничего не пишут.

## Требования

Claude Code **не ниже 2.1.242**. Порог складывается из двух причин: `SendMessage` и
`ListAgents`, на которых держатся диспетчер и правила про параллельные сессии, доехали до
всех платформ на 2.1.234; а запись зависимости с указанием маркетплейса — именно так плагин
объявляет `superpowers` — разрешается верно с 2.1.242. `/mast-ru:init-project` сам проверяет
версию в описи и говорит, какая часть метода не заработает.

Плагин **зависит от `superpowers@claude-plugins-official`**, и Claude Code ставит его вместе
с MAST: скилл сессии пункта передаёт планирование в `superpowers:writing-plans`. Без этого
плагина метод работает — скилл велит расписать задачи плана самому, — но передача
планирования и есть тот путь, под который он сделан.

## Установка

```bash
claude plugin marketplace add ex3del/mast
claude plugin install mast-ru@ex3del --scope user
```

**Язык — это то, какой плагин вы ставите.** `mast-ru` несёт русские тексты, `mast` —
английские; ставьте один из двух, не оба, иначе в каждую сессию приедут две копии ядра.
Код и репозиторий у них общие, различаются только тексты. Сменить язык позже — удалить один
плагин и поставить второй:

```bash
claude plugin install mast@ex3del --scope user
```

Затем включите автообновление — этот шаг легко пропустить, а делать этого не стоит:
у сторонних маркетплейсов оно **по умолчанию выключено**. Либо через меню `/plugin` внутри сессии (маркетплейс
`ex3del` → включить автообновление), либо строкой в своём `~/.claude/settings.json`:

```json
{ "extraKnownMarketplaces": { "ex3del": { "source": { "source": "github", "repo": "ex3del/mast" }, "autoUpdate": true } } }
```

Без этого шага новые версии не доедут: Claude Code проверяет только маркетплейсы
с включённым автообновлением, фоново, примерно раз при старте сессии со случайной задержкой
до десяти минут; свежая версия подхватывается при следующем старте или командой
`/reload-plugins`.

## Что делает `/mast-ru:init-project`

Один сценарий и для пустого проекта, и для проекта с историей: команда сначала проводит
опись (стек, тесты, уже существующие `CLAUDE.md`/`ROADMAP.md`/`TODO.md`/`CHANGELOG.md`,
правила в `.claude/rules/`, remote и ветка по умолчанию, открытые issue), затем идёт по
файлам. Файла ещё нет — он создаётся из шаблона плагина (`CLAUDE.md`, `ROADMAP.md`, пример
`.claude/rules/*.md` с `paths:`, строка `.claude/worktrees/` в `.gitignore`). Файл уже есть —
показывается дифф «было → станет» и отдельный вопрос; молчаливой перезаписи нет, а отказ
человека — законный исход, а не ошибка. Флаг `/mast-ru:init-project --check` показывает ту же
опись и те же диффы, ничего не создавая и не меняя, — принудительный предпросмотр для
проекта, который вы ещё не готовы отдать команде целиком.

Ограждения сценария: критерий «Готово когда» никогда не придумывается — расплывчатая
формулировка переносится как есть с пометкой «незамеренный критерий, нужно ваше число»;
существующий файл переписывается только на чистом дереве git, тогда дифф и откат —
`git diff`/`git checkout` в одну команду; ничего не создаётся и не меняется без вопроса.

## Ядро и скиллы — разный вес

Два разных веса — не случайно. **Ядро** — `locales/<язык>/core.md` — автоматически
вкладывается в каждую сессию хуком `SessionStart`, ограничено 7000 символами (лимит самой
площадки на одну вставку — 10 000): куда записывать решение, порядок «план прежде кода»,
как сессии помечают, что заняты задачей, и как не затоптать чужую незакоммиченную работу.
Это горстка правил, без которых метод ломается. Всё более тяжёлое — как взять пункт
роадмапа в работу или закрыть его, как устроена структура документов проекта, полный цикл
worktree/вливание/диспетчер — живёт в **скиллах** и подгружается, только когда его описание
подходит к текущей задаче, поэтому в сессиях, где это не нужно, ничего не стоит.

## Context7 в комплекте

Плагин несёт MCP-сервер [Context7](https://context7.com) (удалённое подключение,
`https://mcp.context7.com/mcp`) — актуальная документация библиотек на расстоянии одного
вызова. Ключ не нужен — бесплатного режима хватает для обычной работы, поэтому обещание
«две команды и готово» держится и здесь. Упёрлись в лимит — добавьте свой ключ в настройках
плагина, поле «Context7 API key»; оно необязательное и хранится как чувствительное.

В комплекте едет и правило — `/mast-ru:init-project` предлагает его отдельным артефактом каркаса
(`.claude/rules/context7.md`): смотреть документацию библиотек, фреймворков, SDK и CLI через
инструмент поиска, а не по памяти. Инструмент назван по роли, а не по точному имени сервера,
поэтому правило работает и с комплектным Context7, и со своим; если свой сервер документации
уже настроен, команда об этом скажет и предложит пропустить.

## Честные ограничения на сегодня

- `hooks/roadmap_lint.py` понимает **только** эти слова статусов и заголовка критерия
  (`запланирован`/`planned`, `в работе`/`in progress`, `готов`/`done`, `снят`/`dropped`,
  «Готово когда»/`Done when`). Свой синоним — и строка перестанет распознаваться.
- В некоторых ограниченных настройках сессии `/mast-ru:init-project` может не суметь прочитать
  собственные файлы шаблонов из каталога плагина; если команда сообщает, что шаблоны
  недоступны, перезапустите сессию с `--add-dir <путь к плагину mast>`.
