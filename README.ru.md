# MAST

*English version: [README.md](README.md)*

**MAST — Method for Agents, Sessions and Tasks.** Способ вести проект силами нескольких
агентов Claude Code так, чтобы они не мешали друг другу, а сделанное не расползалось.

## Откуда он взялся

Всё началось с режима ultracode: он запускает десятки агентов разом, и уследить, кто что
делает и что уже готово, невозможно. Хотелось того же размаха, но под контролем. Нужные
куски нашлись у других:

- **[beads](https://github.com/steveyegge/beads)** — задачи живут в трекере, понятном
  агентам: что свободно, что занято, что чего ждёт. *Но* это отдельная база (Dolt) со своим
  CLI, во встроенном режиме в неё пишет один процесс, а задачи уходят из текста рядом с
  кодом — для небольшого проекта хозяйства больше, чем пользы;
- **[Agent Teams](https://code.claude.com/docs/en/agent-teams.md)** — роль диспетчера и
  агенты, которые пишут друг другу, а не только человеку. *Но* функция экспериментальная и
  устроена как «лид раздаёт подчинённым»: лида не сменить, одна команда на сессию, а
  помощники не переживают `/resume`;
- **[claude-squad](https://github.com/smtg-ai/claude-squad)** — у каждой задачи своя
  рабочая копия, и агенты не топчут чужие файлы. *Но* это отдельная программа поверх tmux,
  а Claude Code теперь сам умеет worktree и фоновые сессии — лишний слой;
- **[superpowers](https://github.com/obra/superpowers)** — дисциплина вокруг кода: сначала
  план, потом тесты и реализация, потом ревью.

Одного не было ни у кого — **единого источника правды**. Когда код пишут агенты, всё
разъезжается: документация отстаёт от кода, решения забываются, и следующая сессия
откатывает то, о чём договорились вчера. MAST собирает работу вокруг документов, которые
пополняются по ходу дела и которым можно верить: роадмап, архив сделанного, правила по
папкам, долги с условием починки.

Позже часть правил пришла из **[Ouroboros](https://github.com/razzant/ouroboros)** —
системы, которая сама переписывает свои правила: повторяющуюся ошибку ловит проверка, а не
ещё один абзац инструкций, и у каждого факта ровно один владелец.

## Как это работает

1. **Правила приезжают сами.** Плагин вкладывает в каждую сессию короткое ядро правил —
   агенту не нужно ничего напоминать.
2. **Каркас.** Команда `/mast-ru:init-project` один раз раскладывает в проекте документы:
   `CLAUDE.md`, роадмап, архив, правила по папкам.
3. **Работа — это пункты.** Задача крупнее одной сессии становится пунктом роадмапа с
   измеримым критерием «Готово когда».
4. **Диспетчер.** Одна сессия в основной копии ведёт роадмап: решает, что брать, и
   запускает на каждый пункт отдельного агента.
5. **Каждому пункту — своя копия.** Агент работает в собственном worktree и ветке, поэтому
   параллельные пункты не мешают друг другу.
6. **Агенты переписываются.** Находки и «готово» уходят диспетчеру сообщением, а не
   теряются в чьём-то контексте.
7. **Вливание и архив.** Диспетчер вливает готовые ветки по одной, а закрытый пункт уезжает
   в архив с замерами «было → стало».
8. **Память — в документах.** Решения, долги и правила записываются рядом с кодом, и
   следующая сессия читает их, а не угадывает.

### Слои документации

Каждый документ отвечает на свой вопрос, и у каждого факта одно место.

**Что делаем**

- `ROADMAP.md` — общий план: только открытые пункты, у каждого — критерий готовности с
  числом, кто его ведёт и от чего он зависит.
- `docs/roadmap/<A-1>/STATUS.md` — подробный план одного пункта: задачи, журнал по шагам,
  проблемы, принятые решения. Переживает перезапуск агента; заводится, только когда пункт
  этого требует.
- `docs/roadmap/inbox/` — находки агентов, которые ещё никто не разобрал.

**Что сделали и почему**

- `docs/roadmap/DONE.md` — архив закрытого: по две строки на пункт — что изменилось, с
  числом, когда и какими коммитами. Отвечает на «а это уже делали?», а подраздел «Снято» —
  на «а это уже пробовали и отказались?».
- `docs/adr/` — почему выбрали именно так: для решений, откат которых дорог. Такое решение
  живёт ещё в правиле для агента и в тесте, который упадёт при откате.
- `TECH_DEBT.md` — что осознанно оставили криво и при каком условии чиним.

**Правила**

- `CLAUDE.md` — паспорт проекта: стек, команды, инварианты. Грузится в каждую сессию,
  поэтому до 200 строк; справочник живёт в `docs/`.
- `.claude/rules/*.md` — договорённости по конкретной папке: приезжают агенту, только когда
  он трогает эти файлы.

Закрытый пункт читается сверху вниз ровно настолько, насколько нужно: строка в архиве →
журнал пункта → почему так решили → сам код в `git diff`.

## Что внутри

Плагин Claude Code, который приносит в проект способ работы: пункты роадмапа с измеримыми
критериями готовности, worktree на пункт, диспетчер для параллельной работы, правила с
`paths:`, архив закрытого. Плагин не трогает глобальный `~/.claude/CLAUDE.md` и ничего не
пишет в ваш проект без вопроса. Сам Claude Code записывает включение плагина в ваш
`settings.json` — такая же служебная запись, как у любого плагина, — а метод и его хуки
туда ничего не пишут.

## Требования

Claude Code **не ниже 2.1.242**. Порог складывается из двух причин: `SendMessage` и
`ListAgents`, на которых держатся диспетчер и правила про параллельные сессии, доехали до
всех платформ на 2.1.234; а запись зависимости с указанием маркетплейса — именно так плагин
объявляет `superpowers` — разрешается верно с 2.1.242. `/mast-ru:init-project` сам проверяет
версию в описи и говорит, какая часть метода не заработает.

Плагин **зависит от `superpowers@claude-plugins-official`**, и Claude Code ставит его вместе
с MAST: скилл сессии пункта передаёт планирование в `superpowers:writing-plans`. Без этого
плагина метод работает — скилл велит расписать задачи плана самому, — но передача
планирования и есть тот путь, под который он сделан.

## Установка

```bash
claude plugin marketplace add ex3del/mast
claude plugin install mast-ru@ex3del --scope user
```

**Язык — это то, какой плагин вы ставите.** `mast-ru` несёт русские тексты, `mast` —
английские; ставьте один из двух, не оба, иначе в каждую сессию приедут две копии ядра.
Код и репозиторий у них общие, различаются только тексты. Сменить язык позже — удалить один
плагин и поставить второй:

```bash
claude plugin install mast@ex3del --scope user
```

Затем включите автообновление — этот шаг легко пропустить, а делать этого не стоит:
у сторонних маркетплейсов оно **по умолчанию выключено**. Либо через меню `/plugin` внутри сессии (маркетплейс
`ex3del` → включить автообновление), либо строкой в своём `~/.claude/settings.json`:

```json
{ "extraKnownMarketplaces": { "ex3del": { "source": { "source": "github", "repo": "ex3del/mast" }, "autoUpdate": true } } }
```

Без этого шага новые версии не доедут: Claude Code проверяет только маркетплейсы
с включённым автообновлением, фоново, примерно раз при старте сессии со случайной задержкой
до десяти минут; свежая версия подхватывается при следующем старте или командой
`/reload-plugins`.

### Вариант установки: ядро во всех проектах

```bash
claude plugin install mast-ru@ex3del --scope user --config always_core=true
```

Чем отличается от установки выше: при обычной ядро приезжает **только** в проект, где
метод уже развёрнут (есть `ROADMAP.md` или `.claude/rules/`), а в остальных вместо него
приходит строка «метод не развёрнут, развернуть — `/mast-ru:init-project`». С
`always_core=true` ядро приезжает **в любой** проект — в неразвёрнутом та же строка
остаётся сверху подсказкой. Больше ничего не меняется: те же скиллы, та же команда, тот же
линт; разница только в том, приходят ли правила туда, где каркаса нет.

Ставьте так, если метод — ваш способ работы вообще, а не только в подготовленных
репозиториях. Цена — примерно 8 тысяч символов в контексте каждой сессии.

- `--config` записывается **только при настоящей установке**. Плагин уже стоит — `install`
  ответит «already installed» и значения не запишет: сначала
  `claude plugin uninstall mast-ru@ex3del`, потом команда выше.
- Значение оседает в `~/.claude/settings.json` — его можно написать и руками:
  ```json
  { "pluginConfigs": { "mast-ru@ex3del": { "options": { "always_core": true } } } }
  ```
- Действует со следующей сессии; в текущей — `/reload-plugins`.

## Что делает `/mast-ru:init-project`

Один сценарий и для пустого проекта, и для проекта с историей: команда сначала проводит
опись (стек, тесты, уже существующие `CLAUDE.md`/`ROADMAP.md`/`TODO.md`/`CHANGELOG.md`,
правила в `.claude/rules/`, remote и ветка по умолчанию, открытые issue), затем идёт по
файлам. Файла ещё нет — он создаётся из шаблона плагина (`CLAUDE.md`, `ROADMAP.md`, пример
`.claude/rules/*.md` с `paths:`, строка `.claude/worktrees/` в `.gitignore`). Файл уже есть —
показывается дифф «было → станет» и отдельный вопрос; молчаливой перезаписи нет, а отказ
человека — законный исход, а не ошибка. Флаг `/mast-ru:init-project --check` показывает ту же
опись и те же диффы, ничего не создавая и не меняя, — принудительный предпросмотр для
проекта, который вы ещё не готовы отдать команде целиком.

Ограждения сценария: критерий «Готово когда» никогда не придумывается — расплывчатая
формулировка переносится как есть с пометкой «незамеренный критерий, нужно ваше число»;
существующий файл переписывается только на чистом дереве git, тогда дифф и откат —
`git diff`/`git checkout` в одну команду; ничего не создаётся и не меняется без вопроса.

## Работа: запуск диспетчера

Главная команда метода. Каркас развёрнут — в **основной копии** проекта запускаете
сессию-диспетчера, и дальше всю цепочку ведёт она:

```bash
cd ~/code/<проект>
claude --name <проект>-dispatch --model opus --advisor fable \
  "Ты диспетчер роадмапа этого проекта: веди его по скиллу mast-ru:managing-roadmap-items. Начни с проверки брошенных пунктов, потом покажи, что готово к взятию."
```

- **`--name <проект>-dispatch`** — по этому имени сессии пунктов находят диспетчера в
  `ListAgents` и шлют ему находки и «готово». Имя с проектом, потому что `ListAgents`
  показывает сессии всех проектов на машине.
- **`--model opus --advisor fable`** — диспетчер решает, что брать, кому и когда вливать;
  на этом не экономят. Есть `opus[1m]` — берите его: диспетчер копит контекст часами.
- **Что он делает:** заводит пункты в `ROADMAP.md`, запускает на каждый сессию в своём
  worktree, разбирает находки, вливает готовые ветки по одной, переносит закрытое в
  `DONE.md`. `ROADMAP.md`, `DONE.md` и `TECH_DEBT.md` правит только он.
- **Сессии пунктов руками не запускаются** — диспетчер стартует их сам фоном:
  `claude --bg --worktree A-1 --name A-1 --advisor fable "…"`, а на пункты, прошедшие
  понижение, — `--model sonnet --advisor opus`. Список — `claude agents`, зайти в
  сессию — `claude attach <id>`.
- **Без диспетчера** можно, пока пункт один: ведите его сами в основной копии, находки
  ложатся файлами в `docs/roadmap/inbox/` и ждут, пока диспетчер появится.

## Ядро: что это и как доезжает

- **Ядро** — `locales/<язык>/core.md`: правила, без которых метод ломается. Куда записывать
  решение, план прежде кода, пометка занятости именем сессии, модель пункта, задача как
  проверяемая цель, параллельные сессии в одной рабочей копии.
- **Приезжает хуком `SessionStart`.** При старте сессии Claude Code запускает `hooks/core.py`,
  и его вывод кладёт в контекст. Ни файла в проекте, ни импорта — только вывод хука.
- **Потолок 8200 символов** при лимите площадки 10 000 на вставку. Что тяжелее, живёт в
  **скиллах**: они грузятся, только когда описание подходит к задаче, и в остальных сессиях
  не стоят ничего.
- **Условие вставки:** в проекте есть `ROADMAP.md` или `.claude/rules/` — ядро целиком; нет
  ни того, ни другого — одна строка «метод не развёрнут, развернуть —
  `/mast-ru:init-project`». Так в чужих репозиториях плагин ничего не весит.
- **Настройка `always_core`** снимает это условие: ядро приезжает и туда, где каркаса ещё
  нет, под той же строкой-подсказкой. Как включить — в разделе «Установка».
- **Язык — это выбор плагина** (`mast-ru` или `mast`), а не настройка внутри одного.

## Context7 в комплекте

Плагин несёт MCP-сервер [Context7](https://context7.com) (удалённое подключение,
`https://mcp.context7.com/mcp`) — актуальная документация библиотек на расстоянии одного
вызова. Ключ не нужен — бесплатного режима хватает для обычной работы, поэтому обещание
«две команды и готово» держится и здесь. Упёрлись в лимит — добавьте свой ключ в настройках
плагина, поле «Context7 API key»; оно необязательное и хранится как чувствительное.

В комплекте едет и правило — `/mast-ru:init-project` предлагает его отдельным артефактом каркаса
(`.claude/rules/context7.md`): смотреть документацию библиотек, фреймворков, SDK и CLI через
инструмент поиска, а не по памяти. Инструмент назван по роли, а не по точному имени сервера,
поэтому правило работает и с комплектным Context7, и со своим; если свой сервер документации
уже настроен, команда об этом скажет и предложит пропустить.

## Честные ограничения на сегодня

- `hooks/roadmap_lint.py` понимает **только** эти слова статусов и заголовка критерия
  (`запланирован`/`planned`, `в работе`/`in progress`, `готов`/`done`, `снят`/`dropped`,
  «Готово когда»/`Done when`). Свой синоним — и строка перестанет распознаваться.
- В некоторых ограниченных настройках сессии `/mast-ru:init-project` может не суметь прочитать
  собственные файлы шаблонов из каталога плагина; если команда сообщает, что шаблоны
  недоступны, перезапустите сессию с `--add-dir <путь к плагину mast>`.
