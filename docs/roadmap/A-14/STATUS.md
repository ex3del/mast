# A-14 `mast merge`: вливание одной командой и rebase очереди готовых веток

**Мои пути:** hooks/**, plugins/*/**, tests/**, README.md, README.ru.md
**Не трогаю:** всё остальное; из общих с соседями — `plugins/*/hooks/hooks.json` не трогаю совсем,
в скилле диспетчера — только разделы «Вливание» и новый «Снятие пункта»

## Устройство (черновик до кода)

- `hooks/mast.py` — CLI на stdlib поверх `roadmap_lint` (`parse`, `lint`, `criterion`, `split_ledger`,
  `ready`); копии в `plugins/*/hooks/` раскладывает `sync_plugins.py`. Обёртка `plugins/<язык>/bin/mast`
  (`exec python3 …/hooks/mast.py <язык> "$@"`) — площадка кладёт `bin/` плагина в PATH Bash.
- `mast merge X-N [--no-push]` в основной копии, на ветке по умолчанию. Всё проверяется и
  считается **до** мерджа, запись — одна:
  1. отказы: строки пункта нет / не «в работе»; ветки `worktree-X-N` нет; не fast-forward; в
     `HEAD..ветка` есть коммит без префикса `[X-N]`; ветка задела `ROADMAP.md`, `docs/roadmap/DONE.md`,
     `TECH_DEBT.md`; в последнем коммите нет строки `Готово когда:` с критерием из `ROADMAP.md`
     дословно (пробелы нормализуются) или нет абзаца `Тезис:`; в `main` уже есть коммиты `[X-N]`
     вне файлов роадмапа (второй заход — к человеку); новые жалобы линта на итоговом состоянии;
     грязные `ROADMAP.md`/`DONE.md`/`TECH_DEBT.md` в основной копии.
  2. `git merge --ff-only`, тезис в `DONE.md` + удаление строки + абзацы `Долг:` в конец
     `TECH_DEBT.md` — одним коммитом `[X-N] закрыт`, `git push` (если есть upstream и нет `--no-push`),
     уборка: `claude rm <id>` сессии с cwd `.claude/worktrees/X-N` (есть `claude`), иначе
     `git worktree remove`; `git branch -d`, удалённая ветка — `git push origin --delete`.
  3. очередь: другие ветки пунктов «в работе», чей последний коммит — готовый (п. 1) и которые
     этот мердж сдвинул (прежний `HEAD` — их предок): rebase во временном worktree, тесты командой
     из `.claude/rules/dispatch.md` (строка `Тесты: \`…\``); чисто — вливается тем же путём; конфликт,
     красные тесты или команды нет — в выводе текст для её сессии.
  4. вывод: что влито, диапазоны, кого ждали (`Зависит от`), `--ready`, файлы в `inbox/`.
- Тезис в `DONE.md`: шапка строится скриптом — `- **X-N** <название> — <ДД.ММ> · \`база..вершина\``
  плюс `[STATUS](done/X-N/STATUS.md)` и `[ADR](../adr/X-N-*.md)`, если есть в ветке; второй строкой —
  абзац `Тезис:` из коммита. Вставка сразу под заголовок раздела своей буквы; раздела нет — в конец.

## Проблемы

- Документация площадки: плагин с `bin/` в корне отклоняется при раздаче через настройки
  организации (claude.ai, «Plugin contains a top-level bin/ directory»). Через маркетплейс
  GitHub — работает. `bin/` выбран в строке пункта — оставлен, запись для `TECH_DEBT.md`.
- Очередь вливает ветки, замеров которых диспетчер не смотрел: проверяется форма
  (критерий дословно, `→`, тезис), не правдивость. До ревьюера A-15 — запись для `TECH_DEBT.md`.
- Команда тестов живёт в `.claude/rules/dispatch.md` (решение в строке пункта), а само
  существование этого файла разрешает `sonnet`. Объявить тесты = открыть понижение — вопрос
  человеку. В этом репозитории файла нет: очередь здесь будет возвращать ветки сессиям.

## Принятые решения

- Готовность ветки для очереди — форма её последнего коммита, а не сообщение диспетчеру:
  сообщения теряются при перезапуске, коммит нет (так и написано в скилле сессии пункта).
  В очередь попадают только ветки, чья база — `HEAD` до этого вызова: скрипт чинит то, что
  сдвинул сам, а ветку на старом `main` отдаёт сессии (отказ «не fast-forward»).
- Rebase очереди — на detached HEAD во временном worktree; ref ветки не двигается (она
  checked out в worktree сессии, `update-ref` рассинхронизировал бы её копию). Влита
  переребейзенная вершина, старая ветка удаляется `-D` только если не сдвинулась после проверки.
- Разбор последнего коммита терпит старую форму (A-11, A-18): «Готово когда (…):», перенос
  строк, «Черновик тезиса для DONE.md:» с шапкой строки. Критерий сверяется дословно с точностью
  до пробелов.
- «Второй заход» — эвристика по теме: коммиты `[X-N]` в `main` вне файлов роадмапа, кроме
  учётных (заведён, взят, критерий изменён, находка). Ложный отказ ведёт к человеку, ложный
  пропуск теряет часть диапазона — склонились к меньшему числу ложных отказов.
- `--no-push`: в этом проекте push сейчас запрещён человеком, без флага `mast merge` здесь
  неприменим. Push только при upstream у ветки, удалённая ветка удаляется, если она там есть.
- Уборка: `claude rm <id>` сессии, чей `cwd` — worktree пункта (по `cwd`, не по имени:
  имя бывает с суффиксом), потом `git worktree remove` без `--force`. Сбой уборки не отменяет
  вливание — строкой в вывод.
