# A-23 Справка сессии при вливании и вопросы к ней после закрытия

**Мои пути:** hooks/**, plugins/*/**, tests/**, README.md, README.ru.md
**Не трогаю:** всё остальное
**Готово когда:** `mast merge` без блока «Справка:» в последнем коммите — отказ 1 из 1, справка длиннее 800 символов — отказ 1 из 1; вывод `mast merge` и тело `[X-N] закрыт` содержат справку, команду вопроса и список файлов, совпадающий с `git diff --stat <база>..<вершина>`, — 1 из 1 на фикстуре; после `mast merge` сессия жива, `mast status` — строка «закрыт, открыта до HH:MM» с `claude attach <id>`, 0 лишних и 0 сирот — 1 из 1; вопрос через `claude attach <id>` в пределах часа — `cache_read_input_tokens` ≥ 90% контекста в транскрипте, 1 из 1 живьём; следующий `mast merge` или `mast start` после порога убирает сессию, worktree и ветку закрытого пункта, до порога не трогает — 2 из 2 на фикстуре; сторож: `mast status` не вызывает `claude rm` и `git worktree remove` — 1 из 1; команда вопроса после часа ровно в том виде, как её печатает `mast status`, на установленном плагине поднимает сессию закрытого пункта, и та отвечает про свой пункт — 1 из 1, после этого `mast status` — 0 лишних; в скилле сессии пункта (ru и en) — блок «Справка:» в последнем коммите, сторож 2 из 2.

> **For agentic workers:** план исполняет эта же сессия (superpowers:executing-plans), шаги — чекбоксы.

**Goal:** после вливания человек получает справку сессии, список файлов и команду вопроса; сессия живёт горячий час и убирается лениво.

**Architecture:** всё в `hooks/mast.py`: блок `Справка:` разбирает `blocks()`, `check()` отказывает; `close()` пишет справку, `git diff --stat` и команду вопроса в коммит закрытия; `merge()` вместо уборки своей сессии зовёт `sweep()` — уборку закрытых пунктов старше часа, её же зовёт `start()` после успеха; `status()` узнаёт закрытый пункт по worktree `X-N` при `X-N` в `DONE.md` вне «Снято» и нет в `ROADMAP.md`. Время последнего сообщения — mtime транскрипта `CLAUDE_HOME/projects/*/<sessionId>.jsonl`.

**Tech Stack:** Python 3 stdlib, pytest, заглушка `claude` из `tests/test_mast_merge.py`.

## Global Constraints

- Порог — константа 60 минут (срок кэша), не настройка и не в `dispatch.md`.
- Справка ≤ 800 символов — считается текст блока без заголовка `Справка:`.
- `mast status` ничего не меняет: ни `claude rm`, ни `git worktree remove`, ни `git branch -d`.
- Отказ `mast merge`/`mast start` ничего не меняет — уборка только после успеха.
- Долларов в выводе нет. Нового файла состояния нет.
- `hooks/` правится в корне, затем `python3 tools/sync_plugins.py`; версия обоих `plugin.json` растёт в первом коммите с `hooks/` или `plugins/`.
- `hooks/mast.py` < 1000 строк (сейчас 862).
- Тексты — парно ru/en.

## Review Focus

- Справка без пустой строки сразу за тезисом — тезис не должен её проглотить (`DONE.md` без справки).
- Закрытый пункт, чья сессия умерла или не нашлась, — worktree не сирота, уборка его всё равно снимает.
- Ветка закрытого пункта ушла вперёд после вливания — уборка не удаляет её (`git branch -d` без `-D`), причина в выводе.
- Снятый пункт с worktree — сирота, как раньше, не «закрыт».
- Сессия с именем закрытого пункта вне его worktree (вопрос после часа) — не «лишняя».

## Проблемы

- `alive()` считал живой сессию со `state` working/blocked без процесса: после обрыва A-23 `mast status` писал «в работе: сессия blocked», а не «брошен» (находка диспетчера 25.09). Живость — по `pid`/`status`.
- `claude rm` отказывает убирать worktree, чьих коммитов нет на удалённом, даже влитых в локальный `main` (живьём 25.09) — уборка без push стояла бы. Починено здесь же: подтверждение `--discard-unpushed` — только для влитой ветки с чистым worktree.
- Драйвер `pty` живого теста висел на `waitpid` убитого `claude` — закрывает терминал до ожидания.

## Принятые решения

- Время последнего сообщения — mtime транскрипта `CLAUDE_HOME/projects/*/<sessionId>.jsonl`: `claude agents --json` его не даёт, а `jobs/<id>/state.json` есть только у `--bg` и формат внутренний; фикстура подделывает mtime через `CLAUDE_CONFIG_DIR`.
- Команда вопроса после часа — `claude --resume <sessionId> --fork-session`: без `--fork-session` площадка отклоняет resume работающей `--bg` сессии, а до уборки она работает; после `claude rm` форк тоже поднимает историю. Из любого каталога (замер: 99% кэша из чужого каталога).
- Уборка — только следующей командой после её успеха и не для только что влитого пункта: иначе пункт без транскрипта (время 0) убирался бы своим же вливанием.
- Ветка при уборке — `git branch -d`, а не сверка с вершиной на момент вливания: вершины через час уже нет, а `-d` сам откажет ветке, ушедшей вперёд.
- Имя закрытого пункта не держит «лишнюю» сессию: пункт не возьмут снова, а форк вопроса после часа живёт под этим именем, пока человек в нём.
- Пинга «влит» нет — по правилу человека «промах — пинга нет». На пробах форк `--fork-session --no-session-persistence` читал кэш сессии на 95–100% (при строке пункта в `ROADMAP.md` и без неё, с хуками и без, после коммита в worktree), но в `mast merge` установленного плагина — дважды 59%: сессия живого теста при первом ходе сама читала общий префикс из прошлого прогона, и форк попадал только в него. Попадание зависит от состояния кэша, которым `mast` не управляет. Час — от последней записи транскрипта, то есть от «готов»: после вливания горячих минут на время ревью (3–7) меньше. Опыт «продлевает ли пинг час» (вопрос в 15:00Z) снят ради сроков.
- `hooks/mast.py` > 1000 строк — словарь текстов в `hooks/mast_texts.py`: отдельная ответственность, код не тронут.
- Справка остаётся в «готов», который видит ревьюер: код входа ревьюера не менялся, но «готов» у всех пунктов стал длиннее — живой замер ревьюера перегнан.
