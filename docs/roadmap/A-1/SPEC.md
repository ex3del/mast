# A-1 · Спека: плагин MAST

**Дата:** 20.09.2026
**Статус:** на согласовании

MAST — Method for Agents, Sessions and Tasks. Плагин Claude Code, который приносит в чужой
проект наш способ работы: роадмап с пунктами, worktree на пункт, диспетчер, правила с `paths:`,
архив закрытого.

## Задача

Метод сейчас живёт в личном `~/.claude/CLAUDE.md` (строки 37–136) и работает только у автора.
Отдать его другому человеку нечем: `install.sh` перезаписывает чужой глобальный конфиг,
а обновлений у него нет вовсе.

Нужен продукт: одна ссылка на GitHub, установка двумя командами, обновления приезжают сами,
личные настройки пользователя не тронуты, тексты на русском и английском.

## Два слоя, которые нельзя смешивать

| Слой | Что это | Как живёт |
|---|---|---|
| **Метод** | ядро правил, скиллы процедур, скрипт-сторож `roadmap_lint.py` | едет плагином, обновляется у всех разом |
| **Каркас** | `ROADMAP.md`, `docs/roadmap/`, `TECH_DEBT.md`, `.claude/rules/*.md`, строки `.gitignore` | пишется один раз в проект пользователя и дальше принадлежит ему |

Обновления метода не трогают каркас: роадмап пользователя — его собственность.

## Ограничения площадки

Проверено по документации Claude Code (агент `claude-code-guide`, 20.09):

- плагин **не может** менять `~/.claude/CLAUDE.md` и `settings.json` пользователя и **не может** класть файлы в его проект;
- плагин **может** нести команды, скиллы, агентов, хуки (`hooks/hooks.json`) и MCP-серверы;
- хук `SessionStart` вкладывает текст в контекст каждой сессии; **лимит 10 000 символов** на одну вставку; хуку доступен `${CLAUDE_PROJECT_DIR}`;
- `userConfig` в `plugin.json` даёт диалог при первом включении; значение читается в скиллах как `${user_config.<ключ>}`, в хуках — через `CLAUDE_PLUGIN_OPTION_<КЛЮЧ>`; в shell-форме хука подстановка запрещена, нужна exec-форма;
- штатного i18n нет: языки решаются двумя комплектами файлов;
- пермишены плагин выдавать не может — их подтверждает человек.

Замер: строки 37–136 `CLAUDE.md` — 10 710 символов, в одну вставку не помещаются. Это и задаёт
разделение ядра и процедур.

## Архитектура

```

│   └── roadmap_lint.py      — проверка формата ROADMAP.md
├── skills/
│   ├── managing-roadmap-items/   — пункт: старт, находка, закрытие; диспетчер
│   ├── project-structure/        — какой документ когда заводится
│   └── worktree-flow/            — цикл worktree и вливание
```

### Ядро: что вкладывает `SessionStart`

Из ста строк движка в ядро идут четыре секции — те, без которых метод ломается молча:

| Секция | Символов | Зачем в ядре |
|---|---|---|
| Где что записывать | 1128 | иначе решения теряются |
| Планирование | 1384 | задаёт порядок: пункт → план → код |
| Кто занят задачей | 719 | иначе сессии сталкиваются |
| Параллельные сессии в одной копии | 1040 | защита чужой незакоммиченной работы |

Итого около 4,3 тыс. символов плюс указатели «подробности — в скилле таком-то». Потолок — 6000.

Остальное уезжает в скиллы и подгружается по надобности: структура документов (2175),
worktree-цикл (2483), диспетчер (1781).

**Когда хук молчит.** `core.py` смотрит на `${CLAUDE_PROJECT_DIR}`: есть `ROADMAP.md` или
`.claude/rules/` — вкладывает ядро целиком; нет — одну строку «в этом проекте метод не развёрнут,
`/init-project` развернёт». Так в чужих проектах пользователя плагин ничего не весит.

### Команда `/init-project`: три режима

| Режим | Что делает |
|---|---|
| `--check` (по умолчанию на проекте с историей) | ревизия: что есть, чего нет, что разошлось с эталоном. **Меняет 0 файлов**, печатает отчёт |
| без флага в пустом или новом проекте | разворачивает каркас: `CLAUDE.md` проекта, `ROADMAP.md`, `docs/roadmap/`, `.claude/rules/` с примером `paths:`, строки в `.gitignore` |
| `--apply` после ревизии | применяет выбранные пункты отчёта, каждый показывает диффом и спрашивает |

Разведка перед любым режимом (параллельно): стек и зависимости, тесты и как они запускаются,
существующий `CLAUDE.md` и его размер, наличие `ROADMAP.md`, `docs/`, `.claude/rules/` и
фронтматтера `paths:` в них, remote и ветка по умолчанию.

Проверки ревизии — то, что проверяемо:

- `CLAUDE.md` длиннее 200 строк → предложить, что вынести в `docs/` и `rules/`;
- нет `ROADMAP.md` → предложить завести, собрав черновик из `TODO.md` и открытых issue, если они есть;
- правило в `.claude/rules/` без `paths:` → показать, во что обходится (грузится всегда);
- пункт в `ROADMAP.md` без «Готово когда» с числом или без `Мои пути` в работе → перечислить;
- нет `.claude/worktrees/` в `.gitignore` при заведённых worktree → предложить строку.

**Инвариант безопасности: ни один режим не перезаписывает существующий файл молча.** Есть файл —
показывается дифф и задаётся вопрос. Отказ пользователя — законный исход, а не ошибка.

### Два языка

Язык выбирается при включении плагина через `userConfig.language` (`ru` по умолчанию, `en`).
Все тексты лежат в `locales/<язык>/`, код и структура общие. Сторож `tests/test_locales.py`
сверяет два комплекта по составу файлов и по дереву заголовков и падает при расхождении —
без него версии разъедутся после первой правки.

## Тесты

| Сторож | Что ловит |
|---|---|
| `test_core_size.py` | ядро любого языка ≤ 6000 символов |
| `test_locales.py` | одинаковый состав файлов и структура заголовков `ru` и `en` |
| `test_roadmap_lint.py` | формат строки пункта, число в «Готово когда», очередь готовых (переносится из `ex3del/claude`) |
| `test_init_check.py` | `--check` на подготовленном каталоге-образце не меняет ни одного файла |
| `test_plugin_manifest.py` | `plugin.json` и `marketplace.json` валидны, пути хуков существуют |

## Порядок работы

1. Скелет репозитория, манифесты, пустые локали, сторожа манифеста и локалей.
2. Ядро: разрезать движок, перенести четыре секции, `core.py` с проверкой проекта, сторож размера.
3. Скиллы: перенести `managing-roadmap-items` из `ex3del/claude`, выделить структуру документов и worktree-цикл.
4. `roadmap_lint.py` и его тесты, хук `PostToolUse` через `${CLAUDE_PLUGIN_ROOT}`.
5. `/init-project`: разведка, `--check`, разворачивание, `--apply`.
6. Английская локаль целиком, сторож локалей зелёный.
7. README на двух языках, проверка установки на чистой машине.

## Нерешённое

- Имя маркетплейса и владелец репозитория на GitHub — от этого зависит строка установки.
- Переносить ли в плагин правило `context7.md`: полезно всем, но это уже не про роадмап.
- Нужен ли режим `--update`, обновляющий управляемый блок в проектном `CLAUDE.md`, или каркас после создания не трогаем никогда.
- Что делать, когда в проекте уже есть свой `ROADMAP.md` в другом формате: мигрировать, оставить в покое или вести рядом.
- Совместимость: минимальная версия Claude Code объявляется только в записи маркетплейса — какую ставить.
