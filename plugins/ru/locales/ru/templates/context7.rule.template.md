# Документация библиотек — через инструмент, не по памяти

- Вопросы синтаксиса API, конфигурации, миграции между версиями и установки
  библиотек, фреймворков, SDK и CLI — сначала смотри через инструмент поиска
  документации, а не по памяти: она может быть устаревшей.
- Не применяй для рефакторинга, отладки собственной бизнес-логики и общих
  вопросов программирования — там инструмент поиска документации не нужен.

## Порядок

1. Найди библиотеку по её имени **и своему вопросу** — получишь идентификатор в
   каталоге (у Context7, который едет с плагином, это `resolve-library-id`).
   Бери точное совпадение имени, а если версия названа — версию.
2. Спроси документацию по этому идентификатору и **полным вопросом**, не одним
   словом (`query-docs`).
3. Ответ не удовлетворил — повтори тот же запрос в углублённом режиме
   (`researchMode: true`): он дороже, зато читает исходники репозиториев и свежий
   веб. Этот повтор делается **до** того, как отвечать по памяти, а не после.
