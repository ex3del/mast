## Работа через worktree

**Каждый пункт роадмапа делается в отдельном worktree и вливается в `main` по готовности.** Исключение — мелкий пункт, пока в основной копии никто больше не работает: пометка `основная копия` вместо worktree.

1. Старт: `claude --bg --worktree A-1 --name A-1` плюс `--model` по правилу из «Диспетчер роадмапа» — фоновая сессия, рабочая копия в `.claude/worktrees/A-1/`, ветка `worktree-A-1`, база — `origin/main` (ветка по умолчанию вашего репозитория; здесь и далее вместо `main` подставь свою, если она называется иначе, например `master`). Команда печатает id: зайти — `claude attach <id>`, список — `claude agents`. Без `--bg` сессия откроется в текущем терминале. Строка пункта в `ROADMAP.md` должна быть запушена до старта, иначе worktree её не увидит.
2. Внутри worktree правки основной копии заблокированы движком (Edit/Write, bash с cwd в основной копии, `git -C` в неё). Это защита, а не сбой: два пункта роадмапа не портят друг другу индекс и не видят чужих полуготовых файлов.
3. Коммиты — с префиксом пункта: `[A-1] описание`. **Сессия пункта в `main` не пушит никогда** — ни `git push`, ни `git push origin <ветка>:main`: вливает только основная копия (шаг 4). Фоновая сессия перед завершением коммитит и пушит сама — только свою ветку `worktree-A-1`, после rebase через `git push --force-with-lease`.
4. Пункт готов (критерий «Готово когда» выполнен, весь набор тестов зелёный) → сессия пункта делает `git fetch origin && git rebase origin/main` у себя и сообщает основной копии. Вливает **основная копия** — из worktree нельзя, `main` занят ею:
   ```bash
   git merge --ff-only worktree-A-1
   git log --format=%h -1 ORIG_HEAD; git log --format=%h -1 HEAD   # диапазон пункта
   # тезис в docs/roadmap/DONE.md, строка из ROADMAP.md удалена → коммит «[A-1] закрыт» → git push
   ```
   Диапазон `<база>..<вершина>` попадает в тезис: `— 17.09 · a1b2c3d..e4f5a6b`, тогда `git diff a1b2c3d..e4f5a6b` — всё, что сделал пункт. Хеши до мерджа никуда не пишем: rebase их меняет.
5. После мерджа — `claude rm <id>` (удалит фоновую сессию и worktree) или `git worktree remove .claude/worktrees/A-1`, затем `git branch -d worktree-A-1` и `git push origin --delete worktree-A-1`.

- `.claude/worktrees/` — в `.gitignore` проекта.
- Нужны gitignored-файлы (`.env` и т.п.) в каждом worktree — перечисли их в `.worktreeinclude` в корне проекта.
- Мелкая правка вне роадмапа — worktree не нужен, делай в основной копии.
- Незапушенные коммиты должны попасть в новый worktree — `"worktree": {"baseRef": "head"}` в settings; по умолчанию база всегда свежий `origin/main`.

## Диспетчер роадмапа

Когда пункты идут параллельно, одна сессия основной копии — **диспетчер**, `--name <проект>-dispatch` (имя с проектом: `ListAgents` показывает сессии всех проектов на машине).

- `ROADMAP.md`, `docs/roadmap/DONE.md` и `TECH_DEBT.md` правит только основная копия — диспетчер или человек. Сессии пунктов шлют диспетчеру находки и «готово» через `SendMessage`; диспетчера нет — находка файлом в `docs/roadmap/inbox/`. Номер пункта назначает только основная копия.
- Диспетчер разбирает находки, назначает номера и зависимости, запускает сессии на готовые к взятию пункты (модель — по правилу ниже), вливает ветки по одной, переносит закрытое в `DONE.md`, снимает блокировки и пишет ждавшим сессиям. Порядок — скилл `mast-ru:managing-roadmap-items`.
- Человека спрашивает, только когда решение меняет смысл или необратимо: критерий «Готово когда», снятие или слияние пунктов с разной целью, конфликт двух пунктов за одни пути, удаление неслитой ветки, срочная находка. Остальное решает сам, причину пишет в сообщение коммита.
- Состояние диспетчера — `ROADMAP.md`, `claude agents`, `git worktree list`, а не его контекст: перезапуск ничего не теряет.
- **Диспетчера нет — его шаги делает человек в основной копии** по разделу «Диспетчер роадмапа» скилла `mast-ru:managing-roadmap-items`, начиная с проверки брошенных пунктов. Находки тем временем копятся в `docs/roadmap/inbox/`, это и есть очередь до его появления.
- Модель пункта по умолчанию — более сильная. Понижение до более экономной — только если ошибка обнаружима сверкой с существующим, обратима одним `git revert` и бьёт по одному пункту. Зоны, для которых всегда нужна сильная модель, проект объявляет у себя в `.claude/rules/dispatch.md`; файла нет — всё идёт на сильную модель, файл есть (пусть без зон) — экономная разрешена по этим трём условиям.
