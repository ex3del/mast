# Пункты роадмапа

**Ядро:** решение, не защищённое тестом, числом или CI-проверкой, отменит тот, кто не читал обсуждения. Скилл держит доказательства в трёх точках: критерий готовности, находка, принятое решение.

Это чек-лист, а не сценарий ответа: выполняй, обоснования не пересказывай.

## Кто ты — что читать

| Ты | Обязательно прочитай в этом скилле |
|---|---|
| сессия пункта — в worktree `X-N` или с пометкой `основная копия` | раздел «Сессия пункта» целиком при старте; перед закрытием перечитай его раздел «3. Закрытие» |
| основная копия — диспетчер `<проект>-dispatch` или человек, ведущий роадмап | раздел «Диспетчер роадмапа» и части раздела «Сессия пункта», на которые он ссылается |

Здесь — общее для обоих: инварианты, формат строки, архив, решения.

## Инварианты

- `ROADMAP.md`, `docs/roadmap/DONE.md` и `TECH_DEBT.md` правит **только основная копия**. Из ветки пункта всё для них едет сообщением диспетчеру.
- **Номер пункта назначает основная копия** — следующий свободный по `ROADMAP.md` и `DONE.md`. Номер из архива занят навсегда.
- **Сессия пункта в worktree в `main` не пушит** — только свою ветку.
- **«Готово когда» содержит проверяемое число** — время, объём, количество, размер, потолок памяти. ❌ «PDF генерируется корректно» ✅ «500 строк < 3 с, файл < 2 МБ».
- **`ROADMAP.md` правится Edit или Write, не `sed`:** после правки хук прогоняет `roadmap_lint.py` и возвращает нарушения, внесённые этой правкой. Правку через Bash он не видит.
- ⚠️ **Числа и имена в примерах скилла вымышлены.** Скопировал цифру из примера — замера не было.

## Строка пункта

```markdown
- **B-4** Экспорт отчётов в PDF — 🔨 в работе · `worktree-B-4` · сессия `B-4` · с 08.09
  Зависит от: B-2
  Мои пути: reports/**, api/routes/export.py
  Готово когда: отчёт на 500 строк < 3 с, пиковая память < 300 МБ.
```

| Слот | Когда обязателен | Что |
|---|---|---|
| статус | всегда | `запланирован` / `🔨 в работе`. `готов` и `снят` в файле не задерживаются: и закрытие, и снятие переносят пункт в `DONE.md` — снятый в подраздел «Снято», строкой с причиной. Пока пункт не перенесён, `снят` несёт причину прямо в строке — иначе через полгода никто не вспомнит, почему бросили. Законны у старых пунктов до переноса |
| где ведётся | в работе | `worktree-X-N` или `основная копия`; не взят — `—` |
| сессия | в работе | имя из `--name`, по нему пишут через `SendMessage`. Жива ли — показывает `claude agents` |
| дата взятия | в работе | брошенный пункт виден по возрасту |
| `Зависит от` | если ждёт | только форма `Зависит от: B-2, A-3`: «блокирует» и «ждёт» проверка не видит |
| `Мои пути` | в работе | что пункт правит. По ним — порог на новый пункт и запрет запускать соседа параллельно |
| Готово когда | всегда | с числом. Источник истины — эта строка |

**Готов к взятию** — `запланирован`, и каждая зависимость **закрыта**: либо `готов`, либо в `DONE.md` вне подраздела «Снято». Зависимость, которую сняли, не выполнена — работу бросили, и пункт ждёт решения человека, а не запуска: `python3 ${CLAUDE_PLUGIN_ROOT}/hooks/roadmap_lint.py --ready ROADMAP.md`. `Зависит от` после закрытия зависимости не чистится.

## Закрытое: четыре слоя

| Слой | Где | Что |
|---|---|---|
| тезисы | `docs/roadmap/DONE.md` | по 2 строки на пункт, по разделам: что изменилось с числом, дата, диапазон коммитов, ссылки вниз |
| как делалось | `docs/roadmap/done/X-N/STATUS.md`, если заводился; иначе сообщения коммитов | журнал, критерий с замерами дословно, решения |
| почему так | `docs/adr/X-N-<тема>.md` | решения, прошедшие планку ниже |
| что поменялось | `git diff <диапазон>` | код |

Спускайся ровно настолько, насколько нужно. Ниже всегда дословный источник — пересказов не заводим.

## Решения

| Что решили | Куда |
|---|---|
| выбор, откат которого правдоподобен и дорог: без контекста захотят вернуть Y, а это сломает что-то или стоит дней | ADR + `rules/` + guard, см. ниже |
| рядовое решение | «Принятые решения» в `STATUS.md` или сообщение коммита |
| осознанно оставили криво | `TECH_DEBT.md`: что криво, чем грозит, **при каком условии чиним**, ссылка на пункт. Выбор отложен с условием возврата — это сюда, а не в ADR |

Решение, прошедшее планку, живёт в трёх местах сразу:

- **`docs/adr/<пункт>-<тема>.md`** — для человека. Имя по номеру пункта уникально, параллельные сессии не сталкиваются. Старые `NNNN-*.md` не переименовываются.
- **`.claude/rules/<подсистема>.md` с `paths:`** — для агента. Имя по верхнему каталогу из `paths:` (`reports/**` → `rules/reports.md`), не по технологии. Заводится в момент решения.
- **Guard** — тест или CI-шаг, падающий на возврате. Одних `rules/` мало: `paths:` не срабатывают на правку из неожиданной папки.

Класс определяется инвариантом, а не инцидентом. Guard, замораживающий случайную форму сбоя — сегодняшнего провайдера, конфиг, порядок шагов, — это тот же патч, только в одежде мета-починки.

## Частые ошибки

| Ошибка | Чем кончается |
|---|---|
| Критерий без числа | приёмка превращается в спор |
| Номер назначила не основная копия | два пункта с одним номером, `git log --grep` смешивает их |
| Переиспользован номер из `DONE.md` | история двух пунктов сливается навсегда |
| Сессия пункта правит `ROADMAP.md` в своей ветке | конфликт при rebase |
| Зависимость записана как «блокирует» или «ждёт» | очередь готовых её не видит, пункт берут раньше времени |
| Решение только в `STATUS.md` или только в `rules/` | архив не читают, `paths:` не срабатывают — решение откатывают |
| ADR на каждое решение | важные тонут среди рядовых |
| Хеш коммита записан до мерджа | rebase его поменял, ссылка битая |
| Один класс ошибки чинится третий раз прозой — правилом в `rules/`, строкой в промпте, пунктом чек-листа | проза не исполняется сама; нужен guard — тест, хук или линт, падающий на возврате |

# Сессия пункта

Читаешь целиком при старте, перед закрытием перечитываешь раздел 3: чек-лист длинный, по памяти его не пройти. Инварианты и формат строки — в разделе «Пункты роадмапа» выше.

## 1. Старт

**Базовый замер — сейчас, а не при закрытии.** Прогони сценарий из «Готово когда» на текущем коде и запиши «до» вместе с командой замера: в `Журнал`, а без `STATUS.md` — телом первого коммита пункта. Функции ещё нет — так и пишешь: команда и «нет, н/д». Без «до» решение остаётся словами.

**`STATUS.md` заводится, только если есть хотя бы один признак:**

1. нужен план из нескольких задач — зовётся `writing-plans`;
2. работа переживёт перезапуск или `/compact` — вернёшься позже или сессию уже перезапускали;
3. рядом идёт пункт по близким путям — нужны `Не трогаю` и журнал договорённостей с соседом.

Нет ни одного — строка в роадмапе плюс коммиты: решения и мелкие находки идут в сообщения коммитов. Признак появился по ходу — заводишь файл тогда же.

### Если `STATUS.md` заведён

Путь один — `docs/roadmap/<пункт>/STATUS.md`. Создаёшь с нашей шапкой. Стоит плагин `superpowers` — дальше зовёшь `superpowers:writing-plans` со словами «файл уже есть по этому пути, допиши в него, путь не меняй» (его дефолт `docs/superpowers/plans/` не используем). Плагина нет — задачи расписываешь сам, по одной проверяемой цели на задачу, и строку шапки `writing-plans` в образце ниже пропускаешь. Дальше ведёшь хвост.

```markdown
# B-4 Экспорт отчётов в PDF
<шапка writing-plans: For agentic workers, Goal, Architecture, Tech Stack, Spec>

**Мои пути:** reports/**, api/routes/export.py        ← наше, копия из строки роадмапа
**Не трогаю:** всё остальное                          ← наше
**Готово когда:** 500 строк < 3 с, файл < 2 МБ         ← наше, копия из строки роадмапа

## Global Constraints / File Structure / Task 1..N     ← writing-plans

## Журнал                                             ← наше
- 08.09 — слой хранилища, миграция 052 (коммит «[B-4] слой хранилища»)
## Проблемы                                           ← наше
## Принятые решения                                   ← наше
- reportlab вместо weasyprint — образ <замер> МБ против <замер> МБ
```

Секции `writing-plans` не дублируешь своими: у него отработан формат задач, но план статичен. Наши секции живые: **`Журнал` пишется в конце каждого шага** — это то, что возвращает контекст после `/compact` и перерыва. В журнале темы коммитов, а не хеши: rebase перед вливанием хеши меняет.

## 2. Находка вне пункта

**Порог.** Новый пункт — только если починка выходит за `Мои пути` или не влезает в текущую сессию: нужен свой критерий с числом и свой замер. Иначе чинишь у себя — строка в `Проблемы`, выбранное значение (таймаут, порог) в `Принятые решения`, без `STATUS.md` то и другое в сообщение коммита. **Оформить пункт дороже, чем починить, — это не пункт.**

Прошла порог — все четыре шага, ни один не пропускается:

1. **Артефакт, а не слова.** Тест, воспроизводящий проблему, с пометкой «ожидаемо падает» (`xfail(strict=True)` в pytest или аналог): просто падающий тест заблокирует твоё вливание. Архитектурная находка тестом не ловится — тогда замер с числом: сценарий, команда, результат. Тест кладёшь туда, где живут тесты его области, — это законное исключение из `Мои пути`. Отдельным коммитом `[B-4] находка: <описание>`, в нём только тест (и inbox-файл, если диспетчера нет) — диспетчер перенесёт его в `main` через `cherry-pick`.
2. **Где ещё та же причина.** Проверить, а не отметить: токен не отзывается при смене пароля — посмотри logout, деактивацию, смену email, отзыв прав. Список проверенного — в запись.
3. **Срочность фактами.** Логи, прод, следы эксплуатации, число задетых — одна строка с цифрой или «в проде не воспроизводится».
4. **Донести до основной копии.** Номер не назначаешь, `ROADMAP.md` в своей ветке не трогаешь. Запись: суть, путь к тесту, ветка и тема коммита находки, проверенные места, срочность, предлагаемые раздел, `Зависит от` и «Готово когда» с числом.

| Ситуация | Что делать |
|---|---|
| в `ListAgents` есть `<проект>-dispatch` | `SendMessage` ему с записью. Ответ — номер пункта, до него номер нигде не пишешь. Ответа нет к закрытию — запись файлом в `docs/roadmap/inbox/` отдельным коммитом |
| диспетчера нет, не срочно | файл `docs/roadmap/inbox/<ДД.ММ>-<слово>.md` в коммите находки — приедет с мерджем. Имена сессий не выдумываешь |
| срочно: прод, эксплуатация | человеку сейчас, отдельным сообщением, не жди мерджа |

**Митигейт в своих путях применяешь, а не предлагаешь** — дешёвое временное смягчение (короче TTL, выключенный флаг) с пометкой «временно»: предложенный, но не применённый митигейт защищает ноль. Митигейт в чужих путях — в запись. Свою задачу не бросаешь.

## 3. Закрытие

Закрыт — когда выполнено **всё**, в этом порядке: замер снимается на том коде, который вольют, то есть после rebase.

- [ ] **Решения разложены** по таблице «Решения» в разделе «Пункты роадмапа» выше. «Принятые решения» заполнены, каждое с причиной и своим числом; без `STATUS.md` они уже в коммитах. Решения, прошедшие планку ADR, — в три места; не было таких — шаг пропускается.
- [ ] **Хвосты разведены:** мелочь в своих путях — доделать; прошедшее порог — находкой по разделу 2; осознанно оставили криво — запись для `TECH_DEBT.md` в сообщение диспетчеру. Ни то, ни другое — не закрыто.
- [ ] **Changelog и пользовательская дока обновлены** или вынесены отдельным пунктом через диспетчера. Фича, о которой пользователь не узнал, не сделана.
- [ ] **Архив:** `git mv docs/roadmap/B-4 docs/roadmap/done/B-4` в своей ветке. Папки не было — пропускаешь.
- [ ] **Свежий `main`:** `git fetch origin && git rebase origin/main` (здесь и далее `main` — ветка по умолчанию вашего репозитория; у вас она может называться иначе, например `master`), зелёный **весь набор тестов проекта**, а не только тесты пункта, `git status` чистый. Свою ветку после rebase пушишь `git push --force-with-lease origin worktree-B-4` — это не вопрос человеку, чужих коммитов в ней нет.
- [ ] **Замер «после»** — на коде после rebase, той же командой, что «до»: было → стало. «До» не снято — замерь на коммите перед первым коммитом пункта.
- [ ] **Последний коммит несёт всё для архива** — сообщения теряются при перезапуске диспетчера, коммиты нет. В его тело:
  - блок «Готово когда» **дословно** из `ROADMAP.md` в `origin/main` (его могли изменить, пока ты работал) с замерами было → стало и командой. С `STATUS.md` — ещё и в его шапку. Копируешь, а не пересказываешь: строку из роадмапа удалят;
  - черновик тезиса для `DONE.md` — две строки: что изменилось и главное число, ссылки на `STATUS.md` и ADR, если есть. Без диапазона — его знает только основная копия;
  - записи для `TECH_DEBT.md`, если остались.

  Коммитить больше нечего — `git commit --allow-empty`.
- [ ] **Сообщение диспетчеру** (нет его — человеку): «B-4 готов, ветка `worktree-B-4` на свежем main, замеры: было → стало» и тот же текст, что в последнем коммите. Дальше ветку не трогаешь. Ответ «не fast-forward» — повтори rebase, тесты и сообщение.

## Частые ошибки

| Ошибка | Чем кончается |
|---|---|
| Находка записана словами, без теста или замера | через месяц её не подтвердить |
| Проверен симптом, а не причина | та же дыра вылезает в соседних местах |
| Пунктом заведена мелочь из своих путей | роадмап растёт быстрее, чем закрывается |
| Митигейт предложен, но не применён | ощущение защиты без защиты |
| Критерий пересказан, а не перенесён дословно | замеры разъезжаются с тем, что принимали |
| Перед вливанием прогнаны только тесты пункта | общий прогон сломан, за пунктом тянется цепочка починок |

# Диспетчер роадмапа

Ты — сессия основной копии `<проект>-dispatch`. Единственный, кто правит `ROADMAP.md`, `DONE.md` и `TECH_DEBT.md` и вливает ветки пунктов. Инварианты, формат строки и архив — в разделе «Пункты роадмапа» выше, путь сессии пункта — в разделе «Сессия пункта» выше, здесь — всё, что делает основная копия.

**Состояние — не в твоём контексте.** После перезапуска восстанавливаешься по `ROADMAP.md`, `claude agents`, `git worktree list`, `ls docs/roadmap/inbox/`. Пометкам в `ROADMAP.md` не верь на слово — первым делом проверка брошенных пунктов.

## Брошенные пункты

После каждого перезапуска и перед каждым запуском новых сессий сверь три источника:

```bash
claude agents --json --all | jq -r '.[] | select(.state=="working" or .state=="blocked" or .status!=null) | .name'  # живые; нет jq — то же глазами в `claude agents --all`
grep -n 'в работе' ROADMAP.md     # кто числится в работе
git worktree list                  # что лежит на диске
```

| Расхождение | Что это |
|---|---|
| пункт «в работе», его сессии нет среди живых | брошен: сессия упала или закончила, не закрыв пункт (`state` у неё `done`, `failed` или `stopped`) |
| worktree есть, пункта «в работе» нет | сирота: пункт закрыт или снят, а worktree остался |
| живая сессия с именем пункта, которого нет «в работе» | лишняя: займёт имя, и новая сессия пункта получит суффикс |

Сам ничего не удаляешь: в worktree могут быть незакоммиченные правки. Список расхождений — человеку одним сообщением, с вариантом для каждого: возобновить (`claude attach <id>` или `claude respawn <id>`), закрыть, снять.

## Когда спрашивать человека

| Спрашиваешь | Решаешь сам |
|---|---|
| изменить «Готово когда» пункта | дубль → дописать к существующему пункту |
| снять пункт, слить пункты с разной целью | раздел, номер, `Зависит от` новой находки |
| два пункта в работе правят одни пути — кого остановить | разбить находку на пункты, если цель у всех одна |
| удалить ветку с неслитыми коммитами, force-push | порядок запуска и вливания |
| срочная находка (прод, эксплуатация) — сразу, отдельным сообщением | вернуть находку отправителю за тестом или числом |
| митигейт, который заметят пользователи | `Зависит от` у новых пунктов и у пунктов, которые их ждут |
| брошенный пункт, сирота-worktree, лишняя сессия — возобновить, закрыть или снять | |
| | вернуть пункт на доработку, если замеров нет ни в журнале, ни в коммитах |

Вопрос человеку — одно сообщение: факты с цифрами (нет цифр — сначала запроси их у сессии пункта), 2–3 варианта, твоя рекомендация. Пока ждёшь ответа, строку не трогаешь, пункт продолжает работу. Решил сам — причина в сообщении коммита.

## Разбор находок

Источники: `SendMessage` от сессий и файлы `docs/roadmap/inbox/` — они приезжают с мерджами, проверяй папку после каждого.

1. **Пункт вообще нужен?** Порог — раздел «2. Находка вне пункта» раздела «Сессия пункта» выше: либо находка вне `Мои пути` отправителя, либо не влезает в его сессию. Мелочь в своих путях без собственного критерия с числом — верни отправителю: пусть чинит у себя и пишет в `Проблемы` или в сообщение коммита. Роадмап, который растёт быстрее, чем закрывается, бесполезен.
2. **Тест есть?** Для архитектурной находки — замер с числом и командой. Нет ни того, ни другого — верни отправителю.
3. **Дубль?** `grep -in '<ключевые слова>' ROADMAP.md docs/roadmap/DONE.md` → дописать к найденному пункту и проверить, что его «Готово когда» покрывает находку числом. Нашёлся в `DONE.md` — смотри, в каком разделе. Среди закрытых значит та же проблема вернулась: новый пункт со ссылкой на старый, старый не переоткрывается. В подразделе «Снято» значит это уже пробовали и отказались — вопрос человеку (см. таблицу «Когда спрашиваешь человека»), а не новый пункт от себя.
4. **Новый пункт:** раздел по смыслу; номер — следующий свободный **по двум файлам** (`grep -n '^- \*\*B-' ROADMAP.md docs/roadmap/DONE.md`), номер из архива занят навсегда; `Зависит от`; «Готово когда» с числом — нет числа, запроси у отправителя. Крупная находка — несколько пунктов, у каждого свой критерий.
5. **Тест — в `main` вместе со строкой.** Иначе пункт попадёт в `--ready` раньше, чем его тест окажется в `origin/main`.
   - Находка пришла через `SendMessage` — в её коммите только тест, забираешь его:
     ```bash
     git cherry-pick -n $(git log worktree-B-4 --format=%h --grep='находка: <тема>' -1)
     ```
     Ветка отправителя при rebase сама выбросит перенесённый коммит.
   - Находка лежит в `inbox/` — она приехала мерджем ветки вместе со своим тестом, `cherry-pick` не нужен. Файл из inbox удаляешь `git rm` в коммите, который заводит пункт.
6. **Проверка и коммит:** `python3 ${CLAUDE_PLUGIN_ROOT}/hooks/roadmap_lint.py ROADMAP.md` → коммит → `git push`. Ответ отправителю — номер пункта.

Сообщения коммитов: `[B-2] заведён: …`, `[A-2] дописана находка: …`, `[B-2] взят в работу · <модель>`, `[B-2] закрыт`, `[A-3] критерий изменён по решению человека: …`.

## Какая модель у пункта

По умолчанию пункт ведёт более сильная модель. Понижение до более экономной — только когда «да» на все три вопроса:

1. **Обнаружимость.** Неверный результат ловится сверкой с уже существующим: тестом, линтером, CI, замером, кодом, спекой, ADR.
2. **Обратимость.** Откатывается одним `git revert`, без потери данных и без действий вне репозитория.
3. **Радиус.** Пострадает только этот пункт, а не все будущие сессии, пользователи или данные.

Нет хотя бы одного — сильная модель. **Сомневаешься — сильная модель:** одна переделка пункта дороже разницы в цене моделей.

Правило держится на свойствах ошибки, а не на названиях областей, поэтому работает в любом проекте. Документация раскалывается тем же первым вопросом: «дописать раздел по существующему коду», «поправить устаревший фрагмент», «тесты по критерию, где число уже написано» — экономная модель; «описать архитектуру, поведение, инварианты, контракт API» — сильная модель, потому что сверять не с чем: текст сам становится источником истины.

**Всегда сильная модель, в любом проекте:** файлы, которые агенты читают как правила — `CLAUDE.md`, `.claude/rules/`, скиллы, промпты. Ошибка в них тихо меняет поведение всех будущих сессий, это самый большой радиус в нашей схеме.

**Чувствительные зоны объявляет проект**, а не этот скилл: `<проект>/.claude/rules/dispatch.md`, по строке на зону — `auth/** · billing/** · db/migrations/** — только сильная модель`. Файла нет — всё идёт на сильную модель: экономную проект подключает осознанно, а не получает по умолчанию. Файл есть, пусть даже без единой зоны, — экономная модель разрешена по трём вопросам.

## Запуск пункта

1. **Что можно брать:** `python3 ${CLAUDE_PLUGIN_ROOT}/hooks/roadmap_lint.py --ready ROADMAP.md`. Два пункта, у которых пересекаются «Мои пути», параллельно не запускаешь.
2. **Строка** — по формату из раздела «Пункты роадмапа» выше: сессия `B-2`, `Мои пути`. `STATUS.md` — только если есть признак из раздела «1. Старт» раздела «Сессия пункта»; признаки «нужен план» и «сосед по близким путям» видны уже при запуске. Коммит `[B-2] взят в работу · <модель>` и `git push` — модель в сообщении, чтобы при закрытии было видно, кто делал работу. Всё это **до старта сессии**: изнутри worktree правки основной копии заблокированы, а worktree создаётся от `origin/main` и без push своей строки не увидит.
3. **Старт:**
   ```bash
   claude --bg --worktree B-2 --name B-2 "Веди пункт B-2 по скиллу mast:managing-roadmap-items-ru: строка в ROADMAP.md и docs/roadmap/B-2/STATUS.md, если заведён. Первым шагом — базовый замер"
   ```
   Пункт прошёл понижение — те же флаги, но с `--model <экономная модель>`.
   Команда печатает id. Имя может оказаться занятым живой старой сессией — тогда движок выдаст `B-2-<слово>`. Это симптом брошенного пункта: разберись со старой сессией (см. «Брошенные пункты»), а не записывай суффикс.
4. **После старта:** человеку — id и `claude attach <id>`.

## Вливание

Сессия пункта пишет «готов, ветка на свежем main». Правила очереди:
- **Готовые ветки — раньше своих коммитов.** Любой твой коммит в `main` ломает fast-forward для ветки, которая уже сделала rebase.
- **По одной ветке.** После каждого мерджа `main` сдвигается, и следующей ветке нужен свой rebase.
- **Сначала замеры.** `git log --format=%B origin/main..worktree-B-2` (и `STATUS.md`, если есть): «до» с даты взятия и «после» — с командой замера. Цифр без команды — вернуть пункт на доработку. Совпадение цифр с примером скилла — повод проверить команду, а не приговор.

Порядок:

1. **Влить:** `git merge --ff-only worktree-B-4`. Не fast-forward — сессия пункта повторяет rebase.
2. **Диапазон — сразу после мерджа и с проверкой чистоты:**
   ```bash
   git log --format=%h -1 ORIG_HEAD; git log --format=%h -1 HEAD
   git log --format=%s ORIG_HEAD..HEAD | grep -vc '^\[B-4\]'   # 0 — в диапазоне только коммиты пункта
   ```
   Не 0 — в ветку попали чужие коммиты, и `git diff` по диапазону покажет не только этот пункт. Диапазон не пишешь, в тезисе вместо него `git log --grep='\[B-4\]'`.
   
   Пункт вливался не одним заходом (ветка мерджилась дважды, часть делалась в основной копии) — диапазонов в тезисе несколько через запятую, каждый проверяется на чистоту отдельно; хоть один грязный — вместо всех `git log --grep`.
3. **Сначала тезис в `DONE.md`, потом удаляешь строку из `ROADMAP.md`.** В обратном порядке хук на мгновение увидит, что пункты с `Зависит от: B-4` ссылаются в никуда. Тезис — черновик сессии из тела последнего коммита ветки плюс диапазон, пересказывать пункт заново не нужно. Раздел — своей буквы (заголовок как в роадмапе, нет — создаёшь), дата — день мерджа, ссылки на `STATUS.md` и ADR — если есть:
   ```markdown
   - **B-4** Экспорт отчётов в PDF — 17.09 · `a1b2c3d..e4f5a6b` · [STATUS](done/B-4/STATUS.md) · [ADR](../adr/B-4-reportlab.md)
     Отчёт на 500 строк рендерится 8.2 с → 2.4 с, пиковая память 210 МБ.
   ```
   Записи для `TECH_DEBT.md` оттуда же — тем же коммитом `[B-4] закрыт`, затем `git push`: иначе ждущие сессии сделают rebase без этого пункта. Запись долга без «чем грозит» или «при каком условии чиним» — вернуть сессии, не додумывать.
4. **Снять блокировки:** `grep -niE 'Зависит от:.*\bB-4\b' ROADMAP.md` — живым сессиям этих пунктов «B-4 в origin/main, сделай rebase», ставшие готовыми к взятию — в очередь запуска.
5. **Убрать:** `claude rm <id>` (сессия и worktree) или `git worktree remove .claude/worktrees/B-4`, затем `git branch -d worktree-B-4` и `git push origin --delete worktree-B-4` — сессия пункта пушила свою ветку, и на `origin` она иначе останется навсегда.

**Снятый пункт уезжает туда же.** Строка удаляется из `ROADMAP.md`, в `DONE.md` заводится подраздел «Снято» и в нём одна строка: номер, название, дата, причина и адрес переноса, если работу передали другому пункту. Папка `docs/roadmap/<X-N>/`, если заводилась, едет туда же — в `done/<X-N>/`, иначе ссылка из строки «Снято» будет битой; папки не было — ссылку не ставишь. Тогда архив отвечает не только на «это уже делали?», но и на «это уже пробовали и отказались?» — иначе отвергнутое живёт только в ADR, если его завели, и через полгода тот же пункт заводят заново.

После вливания:
- `ls docs/roadmap/inbox/` — ветка могла привезти находки;
- `python3 ${CLAUDE_PLUGIN_ROOT}/hooks/roadmap_lint.py ROADMAP.md` — заодно покажет тезисы с битыми ссылками на `done/`;
- `python3 ${CLAUDE_PLUGIN_ROOT}/hooks/roadmap_lint.py --ready ROADMAP.md` — что стало можно запускать.

## Частые ошибки

| Ошибка | Чем кончается |
|---|---|
| Запустил сессию до push строки | worktree от `origin/main` не видит своей строки, сессия берёт пункт заново |
| Влил две ветки подряд без rebase второй | не fast-forward или молча смешанные изменения |
| Спросил человека о дубле или номере | человека дёргают по механике, важный вопрос тонет |
| Завёл пункт на мелочь, которую отправитель мог починить у себя | роадмап растёт быстрее, чем закрывается |
| Отдал экономной модели работу, где текст становится источником истины | ошибку не с чем сверить, она тиражируется по ссылкам |
| Оставил закрытый пункт в `ROADMAP.md` | рабочий файл раздувается, `--ready` тонет в готовом |
| Изменил «Готово когда» сам | приёмка по критерию, с которым человек не соглашался |
| Держал очередь в голове, а не в `ROADMAP.md` | после перезапуска очередь потеряна |
