# Пункты роадмапа

**Ядро:** решение, не защищённое тестом, числом или CI-проверкой, отменит тот, кто не читал обсуждения. Скилл держит доказательства в трёх точках: критерий готовности, находка, принятое решение.

Это чек-лист, а не сценарий ответа: выполняй, обоснования не пересказывай.

## Кто ты — что читать

| Ты | Что прочитать **рядом с этим файлом**, прямо сейчас |
|---|---|
| сессия пункта — в worktree `X-N` или с пометкой `основная копия` | `managing-roadmap-items-item.md` целиком при старте; перед закрытием перечитай его раздел «3. Закрытие» |
| основная копия — диспетчер `<проект>-dispatch` или человек, ведущий роадмап | `managing-roadmap-items-dispatcher.md` и те части `…-item.md`, на которые он ссылается |

Файл своей роли читаешь целиком, чужой — не читаешь: сессия пункта не вливает ветки и не правит `ROADMAP.md`, ей незачем держать в голове процедуры диспетчера.

Здесь — общее для обоих: инварианты, формат строки, архив, решения.

## Инварианты

- `ROADMAP.md`, `docs/roadmap/DONE.md` и `TECH_DEBT.md` правит **только основная копия**. Из ветки пункта всё для них едет сообщением диспетчеру.
- **Номер пункта назначает основная копия** — следующий свободный по `ROADMAP.md` и `DONE.md`. Номер из архива занят навсегда.
- **Сессия пункта в worktree в `main` не пушит** — только свою ветку.
- **«Готово когда» содержит проверяемое число** — время, объём, количество, размер, потолок памяти. ❌ «PDF генерируется корректно» ✅ «500 строк < 3 с, файл < 2 МБ».
- **`ROADMAP.md` правится Edit или Write, не `sed`:** после правки хук прогоняет `roadmap_lint.py` и возвращает нарушения, внесённые этой правкой. Правку через Bash он не видит.
- ⚠️ **Числа и имена в примерах скилла вымышлены.** Скопировал цифру из примера — замера не было.

## Строка пункта

```markdown
- **B-4** Экспорт отчётов в PDF — 🔨 в работе · `worktree-B-4` · сессия `B-4` · с 08.09
  Зависит от: B-2
  Мои пути: reports/**, api/routes/export.py
  Готово когда: отчёт на 500 строк < 3 с, пиковая память < 300 МБ.
```

| Слот | Когда обязателен | Что |
|---|---|---|
| статус | всегда | `запланирован` / `🔨 в работе`. `готов` и `снят` в файле не задерживаются: и закрытие, и снятие переносят пункт в `DONE.md` — снятый в подраздел «Снято», строкой с причиной. Пока пункт не перенесён, `снят` несёт причину прямо в строке — иначе через полгода никто не вспомнит, почему бросили. Законны у старых пунктов до переноса |
| где ведётся | в работе | `worktree-X-N` или `основная копия`; не взят — `—` |
| сессия | в работе | имя из `--name`, по нему пишут через `SendMessage`. Жива ли — показывает `claude agents` |
| дата взятия | в работе | брошенный пункт виден по возрасту |
| `Зависит от` | если ждёт | только форма `Зависит от: B-2, A-3`: «блокирует» и «ждёт» проверка не видит |
| `Мои пути` | в работе | что пункт правит. По ним — порог на новый пункт и запрет запускать соседа параллельно |
| Готово когда | всегда | с числом. Источник истины — эта строка |

**Готов к взятию** — `запланирован`, и каждая зависимость **закрыта**: либо `готов`, либо в `DONE.md` вне подраздела «Снято». Зависимость, которую сняли, не выполнена — работу бросили, и пункт ждёт решения человека, а не запуска: `python3 ${CLAUDE_PLUGIN_ROOT}/hooks/roadmap_lint.py --ready ROADMAP.md`. `Зависит от` после закрытия зависимости не чистится.

## Закрытое: четыре слоя

| Слой | Где | Что |
|---|---|---|
| тезисы | `docs/roadmap/DONE.md` | по 2 строки на пункт, по разделам: что изменилось с числом, дата, диапазон коммитов, ссылки вниз |
| как делалось | `docs/roadmap/done/X-N/STATUS.md`, если заводился; иначе сообщения коммитов | журнал, критерий с замерами дословно, решения |
| почему так | `docs/adr/X-N-<тема>.md` | решения, прошедшие планку ниже |
| что поменялось | `git diff <диапазон>` | код |

Спускайся ровно настолько, насколько нужно. Ниже всегда дословный источник — пересказов не заводим.

## Решения

| Что решили | Куда |
|---|---|
| выбор, откат которого правдоподобен и дорог: без контекста захотят вернуть Y, а это сломает что-то или стоит дней | ADR + `rules/` + guard, см. ниже |
| рядовое решение | «Принятые решения» в `STATUS.md` или сообщение коммита |
| осознанно оставили криво | `TECH_DEBT.md`: что криво, чем грозит, **при каком условии чиним**, ссылка на пункт. Выбор отложен с условием возврата — это сюда, а не в ADR |

Решение, прошедшее планку, живёт в трёх местах сразу:

- **`docs/adr/<пункт>-<тема>.md`** — для человека. Имя по номеру пункта уникально, параллельные сессии не сталкиваются. Старые `NNNN-*.md` не переименовываются.
- **`.claude/rules/<подсистема>.md` с `paths:`** — для агента. Имя по верхнему каталогу из `paths:` (`reports/**` → `rules/reports.md`), не по технологии. Заводится в момент решения.
- **Guard** — тест или CI-шаг, падающий на возврате. Одних `rules/` мало: `paths:` не срабатывают на правку из неожиданной папки.

Класс определяется инвариантом, а не инцидентом. Guard, замораживающий случайную форму сбоя — сегодняшнего провайдера, конфиг, порядок шагов, — это тот же патч, только в одежде мета-починки.

## Частые ошибки

| Ошибка | Чем кончается |
|---|---|
| Критерий без числа | приёмка превращается в спор |
| Номер назначила не основная копия | два пункта с одним номером, `git log --grep` смешивает их |
| Переиспользован номер из `DONE.md` | история двух пунктов сливается навсегда |
| Сессия пункта правит `ROADMAP.md` в своей ветке | конфликт при rebase |
| Зависимость записана как «блокирует» или «ждёт» | очередь готовых её не видит, пункт берут раньше времени |
| Решение только в `STATUS.md` или только в `rules/` | архив не читают, `paths:` не срабатывают — решение откатывают |
| ADR на каждое решение | важные тонут среди рядовых |
| Хеш коммита записан до мерджа | rebase его поменял, ссылка битая |
| Один класс ошибки чинится третий раз прозой — правилом в `rules/`, строкой в промпте, пунктом чек-листа | проза не исполняется сама; нужен guard — тест, хук или линт, падающий на возврате |
