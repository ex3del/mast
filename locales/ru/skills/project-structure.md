## Структура проекта

Документы заводятся **по мере надобности**, не все сразу. У каждой истины один владелец —
эта таблица; факт переехал, значит все ссылки на него правятся тем же коммитом. Система,
которая говорит о себе две разные вещи, не способна увидеть собственное противоречие.

| Документ | Когда появляется | Что внутри |
|---|---|---|
| `CLAUDE.md` | сразу | стек, команды, инварианты проекта. Цель — до 200 строк |
| `ROADMAP.md` | сразу | разделы буквами (A, B, C…), пункты цифрами внутри раздела: `A-1`, `B-3`. Плоский список. Держит только открытое: `запланирован`, `🔨 в работе`. Закрытое и снятое уезжают в `docs/roadmap/DONE.md` — `готов` и `снят` в файле не задерживаются (у старых пунктов до переноса допустимы). Номер нового пункта — следующий свободный по обоим файлам (проверь грепом), назначает его основная копия; номер из архива занят навсегда, закрытые пункты не переоткрываются. Пункт в работе несёт имя своего worktree, зависимости — поле `Зависит от: A-3`. Правит только основная копия (см. скилл `mast:worktree-flow-ru`) |
| `docs/roadmap/DONE.md` | при первом закрытом или снятом пункте | закрытые пункты, по 2 строки: что изменилось с числом, дата, диапазон коммитов, ссылки на `done/<пункт>/STATUS.md` и ADR, если они есть. Снятые — подразделом «Снято», по строке с причиной. Первый слой поиска «а это уже делали?» и «а это уже пробовали и отказались?» |
| `TECH_DEBT.md` | при первом долге | что криво, чем грозит, **при каком условии чиним** — это условие-триггер («счёт > $5»), им долг и отличается от пункта роадмапа с его «Готово когда». Ссылка на пункт обязательна: где долг выявлен, а при закрытии — какой его закрыл; закрытый долг сжимается в одну строку, проза уезжает. Класс ошибки, который чинится второй раз, — тоже долг: что за класс, чем грозит, условие починки «повторится ещё раз» и каким guard'ом закрывается |
| `docs/roadmap/<A-1>/STATUS.md` | только при одном из признаков: нужен план из нескольких задач; работа переживёт перезапуск или `/compact`; рядом идёт пункт по близким путям. Иначе — строка в `ROADMAP.md` и коммиты | ведёт скилл `mast:managing-roadmap-items-ru`; сам пункт делается в своём worktree (см. скилл `mast:worktree-flow-ru`). При закрытии уезжает в `docs/roadmap/done/<A-1>/` вместе с критерием и замерами |
| `docs/roadmap/inbox/` | при первой находке из worktree, когда диспетчера нет | находка файлом до разбора, без номера; разбирает диспетчер |
| `.claude/rules/*.md` | когда появилась договорённость про конкретную папку | см. раздел «Где что записывать» в ядре метода |

Справочник — архитектура, схемы БД, карточки воркфлоу — в `docs/`, **не в `CLAUDE.md`**. CLAUDE.md грузится в каждую сессию целиком, `docs/` читается по ссылке только когда нужен.
