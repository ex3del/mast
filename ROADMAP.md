- **A-26** Диспетчер не выполняет прод-команды: хук отклоняет, выкладку после вливания делает сессия пункта — 🔨 в работе · `worktree-A-26` · сессия `A-26` · с 28.09
  Зависит от: A-25
  У `reinhold-dispatch` прод — 324 из 998 вызовов Bash, вывод прод-команд — 255 из 1188 КБ результатов в его контексте (22%), 77 сообщений про очередь на тестовый контейнер; в 37 из 66 выкладок после вливания сессия пункта уже молчала, проверить выкладку было некому ([ресёрч](docs/research/2026-09-25-prod-ops.md), разделы 1.3, 4, 5). Проза не держит: за 47 ч диспетчер один раз позвал субагента и 229 раз читал прод сам. Решение человека 28.09: делать. PreToolUse: основному потоку `*-dispatch` — отказ на Bash и PowerShell с прод-командой, причина «выкладку делает сессия пункта, состояние — субагентом»; субагенту (во входе хука есть `agent_id`) — пропуск любой команды: отличать чтение от записи — эвристика с ложными отказами. Прод-команды — встроенный базовый список внешних инструментов (`ssh`, `scp`, `rsync` на хост, `aws s3`, `mc`, `rclone`, `lakectl`, `clearml-*`, `kubectl`, `dvc push/pull`, `docker --context`/`-H`, `DOCKER_CONTEXT=`/`DOCKER_HOST=`) плюс строки `Прод:` из `.claude/mast.md` (A-25). Разбор по сегментам с маской кавычек, тело `ssh … <<` и `bash <<`, файл из `bash <файл>` — перенести из `measure.py` ресёрча: подстрока `ssh|docker` дала бы 17% ложных отказов. Решение человека 28.09 о цене: хук зовётся фильтром `if` только на команды, начинающиеся с внешнего инструмента (`ssh`, `scp`, `rsync`, `aws`, `mc`, `rclone`, `lakectl`, `clearml*`, `kubectl`, `dvc`, `docker`, `curl`, `bash`, `sh`, `DOCKER_CONTEXT=` и подобные), а не на каждую команду оболочки: хук на каждую — плюс ~12 мс у всех пользователей плагина сверх принятого 24.09 потолка 20 мс в среднем (сейчас 17). Цена решения: шаблон `Прод:`, начинающийся не с такого инструмента (`python scripts/…`, сам ходящий в ClearML или S3), хук не увидит; вернуться после замера `measure.py` на рабочей машине человека. Полноту через фильтр — на той же фикстуре. Код — модулем с ленивым импортом (`.claude/rules/hooks.md`). Первый шаг — живьём: есть ли `agent_id` во входе хука у субагента; нет — вопрос человеку до кода. Числа критерия — по фикстуре вырезанных команд диспетчера `83cd81f4` в `tests/`: транскриптов reinhold в репозитории нет. `mast merge`: есть строка `Прод:` в `.claude/mast.md` — печатает текст для сессии влитого пункта «влито — если пункт требует выкладки, выложи по процедуре проекта и пришли проверку», диспетчер пересылает его, как «сделай rebase»; базовый список этот текст не включает. Главный пользователь — ML-проект человека на Windows, хуки плагина там живьём не проверены (долг в `TECH_DEBT.md`).
  Мои пути: hooks/**, plugins/*/**, tests/**, CHANGELOG.md, CHANGELOG.ru.md, README.md, README.ru.md
  Готово когда: по фикстуре команд `83cd81f4` — отказ на 324 из 324 прод-вызовов, ложных отказов на 674 непрод-вызовах ≤ 1%; живьём на установленном плагине: у сессии `<проект>-dispatch` `ssh` на хост — отказ 1 из 1, та же команда её субагентом — выполнена 1 из 1, у сессии пункта — выполнена 1 из 1; `mast merge` в проекте со строкой `Прод:` — текст выкладки для сессии пункта 1 из 1, без строки — 0; накладные хуков на Bash вне роли диспетчера — парным замером `tools/hook_overhead.py --mix` по транскриптам человека, в среднем не выше 25 мс (изменено по решению человека 28.09: потолок 20 мс не держит ни один вариант защиты — до пункта уже 18,9 мс, один старт хука 14,5 мс).
